# Human Handoff Evidence

This package demonstrates a real same-session human-in-the-loop handoff for an irreversible synthetic action.

## Generation

Generated by the HITL demo against the local synthetic banking application. Replay reached the final `confirm-create` step, policy returned `HUMAN_APPROVAL_REQUIRED`, automation paused, and HUMAN took ownership of the same live browser session.

The demonstrated control flow is:

```text
REQUIRE_HUMAN
→ automation pauses
→ HUMAN acquires the same live BrowserContext/Page
→ human performs the manual action
→ human resumes automation
→ automation re-observes the live state
→ paused postcondition is verified
→ no duplicate risky action is executed
→ success
```

The implementation also supports abort instead of resume; the frozen package records the successful resume path.

## Expected result

- Source actor: `REPLAY`
- Capability: `prepare_new_savings_subaccount`
- Step: `confirm-create`
- Reason: `HUMAN_APPROVAL_REQUIRED`
- Same live session preserved across takeover
- Manual action recorded in the intervention audit trail
- Automation control restored to REPLAY
- `manualStepResolved = true`
- `duplicateRiskyActionExecuted = false`
- Terminal state: `Sub-account created`

## Important files

- `run.json` — sanitized source-run metadata
- `intervention.json` — intervention request, control transitions, human action, and audit trail
- `events.jsonl` — structured events across the same logical run
- `result.json` — terminal result, including duplicate-action protection
- `screenshots/` — four correlated handoff checkpoints
- `SHA256SUMS.txt` — expected SHA-256 hashes for the frozen package

The package records semantic human actions only. It does not persist raw mouse coordinates, keystrokes, cookies, tokens, credentials, `BrowserContext` objects, or `Page` handles.

## Integrity

Run:

```sh
npm run verify-human-handoff-evidence
```

The verifier checks the frozen package against `SHA256SUMS.txt` and validates the expected correlated handoff evidence.
